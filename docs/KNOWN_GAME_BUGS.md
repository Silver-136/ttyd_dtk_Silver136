# Known game bugs

Adapted from the page of the same name in llc00lt's tree (LLCOOLT/ttyd), used with permission, and checked against this tree.

The builds are byte-identical, so the code reproduces the original game's bugs too. This page lists the notable ones found so far (crashes, wrong game logic, things a player or modder may run into), with the place in the code; most are also marked in the source with a `// BUG:` comment. The source has many more `// BUG:` comments for smaller code-level slips (in the libraries, the test REL and single scripts); those are documented only where they are. Do not fix them in the matching code: a fix changes the output. A mod that wants the fix can make it, and the comment says what the fix is.

Each entry names the file and the function (or script) that holds the bug, with a short quote of the line where that helps; search for the `BUG` comment in that function.

## Crashes and memory corruption

| Where | Versions | Bug |
|---|---|---|
| `src/driver/msgdrv.c`, `msgWindow_Entry` (the `windowEntry` result is used unchecked) | both | `msgWindow_Entry` does not check the window id: when all 7 window slots are in use, `windowEntry` returns -1 and the window setup writes before the start of the window table. |
| `rels/bom/src/bom_01.c`, script `minnnanokoe_evt`; `rels/las/src/las_29.c`, script `last_evt_3_2`; `rels/mri/src/mri_00.c`, script `minnnanokoe_evt` | both | These scenes open a new message window every 300 ms (bom_01, mri_00) or 200 ms (las_29, ten windows) with no other check, which is not always enough for the old ones to close; together with the bug above, too many open windows corrupt memory. |
| `src/driver/msgdrv.c`, `msgWindow_Entry` (the allocation before the `strcpy`) | both | The message copy is allocated with `strlen(msg)` bytes, without room for the terminator, so `strcpy` writes one byte past the block. |
| `src/mario/mario_motion.c`, `mot_talk` (the `fbatGetPointer()->npc` read) | both | Mario's pose change after a conversation uses `fbatGetPointer()->npc`, the NPC Mario last talked to or fought, which may belong to another map. |
| `src/event/evt_map.c`, `evt_map_blend_set_flag` (the `"party"` branch) | both | No check that a partner (or a follower) is out: `partyGetPtr` returns NULL for id -1 and the partner's animation group is read through a null pointer. |
| `src/mario/mario_pouch.c`, `pouchInit` | both | `pouchInit` allocates a new inventory without freeing the old one. It runs at boot and again when a new file starts, so the first block leaks. |
| `src/driver/msgdrv.c`, `msgAnalize` (the `<select>` tag's `sscanf`) | both | The format has five `%hd` but only four pointers follow, so a `<select>` tag with a fifth number writes it through whatever is in the next argument register. |
| `src/driver/lightdrv.c`, `lightEntry` (the `name_0000` loop) | both | When the name is taken, the loop formats `uniqueName` from `name` and then points `name` at `uniqueName`; on a second clash `sprintf` reads its own output buffer, so the suffixes stack up (and the copy overlaps). |

## Softlocks and unusable saves

Reported by Zephiles (2026-11-11) and checked against the code.

| Where | Versions | Bug |
|---|---|---|
| `src/driver/msgdrv.c`, `msgWindow_Main` (`MSG_WIN_STATE_REVIEW_KEY_WAIT`) | JP and the early demos (fixed in US) | While paging back through a message, several buttons are handled in the same frame. With the window two or more pages back, B and Z together set the last page and then step back one page into `REVIEW_UP`, whose scroll test never passes for a page further down; nothing leaves that state and the window never closes. |
| `src/manager/cardmgr.c`, `cardWrite` and `cardCopy2Main` (`gp->softResetWait`) | JP and the early demos (fixed in US) | Neither saving nor loading clears `softResetWait`. A file saved while the soft-reset buttons were held keeps the flag, its old timeout and the held buttons, so right after loading it the reset check (`viPostCallback`) soft-resets the game, every time. |
| `src/mario/mario.c`, `marioCheckMenuDisable` (the Vivian test) | JP and the early demos (fixed in US) | While Mario hides in Vivian's shadow the pause menu is allowed even when a script is using Vivian (`PARTY_FLAG_IS_EVT_USE`), so it can open in the middle of that script. |

## Wrong logic

| Where | Versions | Bug |
|---|---|---|
| `src/driver/icondrv.c`, `iconNumberDispGx3D` (`s32 digits[4]`) | both | The digit array is one short: the ten-thousands digit is stored in the first word of the matrix `m`, which `MTXTrans` overwrites before the loop draws it, so a 3D icon number of 10000 or more indexes the digit table with the bits of a float (a wrong or garbage icon for the leading digit). |
| `src/driver/icondrv.c`, `iconMain` (the deferred set-up of an entry made before icon.bin had loaded) | JP and the early demos (fixed in US) | The set-up reads the icon size and frames through `data` without fetching it for this entry, so it uses whatever `data` holds (uninitialised, or left from an earlier entry's animation step). | `src/event/evt_mobj.c`, `mobj_lock` (the `pouchCheckItem` result) | JP and the early demos (fixed in US) | For locks with a key list (only `mobj_lock01` in `rels/mri/src/mri_03.c`), the key lock stores the *count* of the key the player holds (from `pouchCheckItem`) instead of its id, and passes that count to `pouchRemoveItem` as an item id. Holding one key removes item id 1. |
| `src/driver/itemdrv.c`, `itemEntry` (the full-table fallback) | JP and the early demos (fixed in US) | With every item slot in use, only the first slot is checked for a replaceable coin, flower or heart, so a replaceable item in any other slot is never freed for the new one. |
| `src/driver/npcdrv.c`, `fbatRecoverItems` and `npcGetBackItemEntry` (`itemFlagOn(itemEntry(...))`) | JP (fixed in US) | `itemEntry` returns NULL when no item slot is free, and the result goes straight to `itemFlagOn`, which dereferences it. |

| `src/countdown.c`, `countDownSaveReStart` | JP and the early demos (fixed in US) | Once the saved time is past the limit, `limit - ms` is negative and the unsigned compare sees a huge value, so the countdown is not set back to its restart time. |

| `src/party/party_motion.c`, `party_motion_jump` (the step limit) | JP and the early demos (fixed in US) | The step limit uses the signed height difference, so for a target below the partner it is negative and the jump distance is clamped to a negative value. |
| `src/window/win_root.c`, `winRootMain` (state 100) | JP and the early demos (fixed in US) | The pause menu tests the menu slot at the tab index, but slot 0 always holds the current tab's entry. |
| `src/driver/msgdrv.c`, `msgAnalize` (the `<pos>` tag) | JP and the early demos (fixed in US) | The scroll is saved outside the `posY != 999` test, so the "keep y" value 999 is stored as a scroll of -999. |
| `rels/muj/src/unit/unit_boss_gundan_zako_group2.c`, `zakogun_ext_main2` (step 50) | JP and the early demos (fixed in US) | The X-Naut target's position is read with no check that the target unit still exists. |
| `rels/mri/src/mri_puni.c`, `puniModeWonder` | JP and the early demos (fixed in US) | The Puni keeps its pop burst in `p->effect`, but that effect deletes itself after 30 frames, so the pointer is stale for the file's `effDelete(p->effect)` checks. |
| `rels/gor/src/gor_01.c`, `R_cookbook_recipe_table` | JP and the early demos (fixed in US) | Slow Shroom + Jammin' Jelly gives Maple Super, while the rows around it give each syrup's own dish; US gives Jelly Super. |

## Fragile but harmless in the shipped game

| Where | Versions | Note |
|---|---|---|
| `src/unit/party/unit_party_nokotarou.c`, Koops's Shell Shield script (the wait loop that reads the shell's unit work into LW(10)) | both | The loop that waits for the shell to finish sliding onto Mario reads the slot into LW(10) but tests LW(0), which holds Mario's unit id, so it stops on its first pass; the script goes on without waiting for the slide. |
| `src/sequence/seq_mapchange.c`, `seq_mapChangeMain` (the `rel_bss` clear before `OSLink`) | both | The REL bss buffer is a fixed 0xF10 bytes and only 0x3C4 of them are cleared; the REL's bss size and alignment are not checked and `OSLink`'s result is ignored. The shipped RELs fit; a modified REL with a larger bss fails to link or overruns the buffer. |
| `src/event/evt_mobj.c`, `evt_mobj_hit_onoff` (`if (mobj->hitObj[i].name)`, twice) | both | `if (mobj->hitObj[i].name)` tests a `char[16]` array, which is always true; the empty-name case is never skipped. |
| `src/driver/mapdrv.c`, `mapObjSetOffScreen` | both | An unknown object name leaves the object pointer NULL and the function writes its offscreen id and flag near address 0; it is only safe while every caller passes a name that exists in the loaded map. |
| `rels/win/src/data/battle/battle_database_win.c`, the two win_02 encounters with `GSWF_WIN_02_ALT_BATTLES_UNUSED` | both | Their alternate battle groups are selected by GSWF 2680, which nothing sets, so the alternates are never used. |
| `src/event/evt_badgeshop.c`, `badgeShop_ThrowCheck` (`bdsw->bargainBadges[i + bdsw->bargainNum]`) | both | The count of a badge among the bargain picks starts at index `bargainNum`, so it reads the unfilled slots and, from 3 picks on, the words after the array (`bargainNum`, `reserved_110`, `restockFlags`, padding). None of them holds a badge id, so it always returns 0 and the badge lists in winmgr.c and evt_win.c subtract nothing; the picked badges are already taken out of `bargain_table` when the list is made, so nothing shows. |
| `src/battle/battle_damage.c`, `BattleCheckDamage` (`irand(100) < 0`) | both | The chance for `SPECIAL_FREEZE_CRUSH` can never pass, so those attacks never break a freeze. With a real chance, the last hit would break the target's freeze and defeat it at any HP. |
| `src/battle/battle_seq.c`, `btlseqAct` (`irand(100) < 0`) | both | The chance for an electrified unit to run `btldefaultevt_BiribiriMove` can never pass. With a real chance, the shock would replace the unit's action for the turn. Feeling Fine blocks Electric along with the harmful statuses. |
| `src/battle/ac/` (`irand(100) >= 0` in 13 action commands; `while (r < 0)` in `ac_repeatedly_lv.c`) | both | A confused auto-play has a success test whose chance is 0, so it always takes the lowest result; the success and random-level branches never run. `ac_shot.c` has no such test: its confused result is random. |
| `rels/aji/src/aji_10.c`, script `aji_10_init_evt` (`GSWF_AJI_10_VISITED`) | both | The script sets the flag and tests it for 0 on the next line, so the east-door lock in that branch never runs. |
| `src/manager/evtmgr_cmd.c`, `evt_debug_put_reg` (the UW, GSW and LSW address branches) | both | In their address-value sub-branches, the `UW` branch prints the value as the index, and the `GSW` and `LSW` branches print the value as the index and pass no argument for the `%08X`, which takes a stray register. The text goes to a static buffer that nothing shows, so there is no effect. |
