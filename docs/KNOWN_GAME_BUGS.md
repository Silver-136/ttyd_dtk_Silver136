# Known game bugs

Adapted from the page of the same name in llc00lt's tree (LLCOOLT/ttyd), used with permission, and checked against this tree.

The builds are byte-identical, so the code reproduces the original game's bugs too. This page lists the notable ones found so far (crashes, wrong game logic, things a player or modder may run into), with the place in the code; most are also marked in the source with a `// BUG:` comment. The source has many more `// BUG:` comments for smaller code-level slips (in the libraries, the test REL and single scripts); those are documented only where they are. Do not fix them in the matching code: a fix changes the output. A mod that wants the fix can make it, and the comment says what the fix is.

Each entry names the file and the function (or script) that holds the bug, with a short quote of the line where that helps; search for the `BUG` comment in that function.

The Versions column names the builds that contain the bug: the code is compiled for that version (its `#if VERSION` tests) and its unit or REL is in that build. The seven builds are the June 2004 US demo and the JP store demo (together "the early demos"), JP, US, the September 2004 US and PAL demos ("the September demos"), and PAL. The early demos and the September demos have only some RELs (the June US demo: gon, hei, kpa, mri, nok, sys; the September demos: gon, gor, hei, kpa, mri, nok, tik). The labels:

- **all**: all seven builds.
- **all but the June US demo**: the code is in a REL (gor, tik) that the June 2004 US demo does not have.
- **retail and the JP demo**: JP, US, PAL and the JP store demo; the code is in a REL that the June US demo and the September demos do not have.
- **JP and the early demos (fixed in US)**: the two early demos and JP; US, the September demos and PAL have the fix.
- **JP and the JP demo (fixed in US)**: the same for a REL that the June US demo does not have.
- **JP only (fixed in US)**: the early demos have older code without the bug; US and later have the fix.

## Crashes and memory corruption

| Where | Versions | Bug |
|---|---|---|
| `src/driver/msgdrv.c`, `msgWindow_Entry` (the `windowEntry` result is used unchecked) | all | `msgWindow_Entry` does not check the window id: when all 7 window slots are in use, `windowEntry` returns -1 and the window setup writes before the start of the window table. |
| `rels/bom/src/bom_01.c`, script `minnnanokoe_evt`; `rels/las/src/las_29.c`, script `last_evt_3_2`; `rels/mri/src/mri_00.c`, script `minnnanokoe_evt` | all (bom_01 and las_29: retail and the JP demo) | These scenes open a new message window every 300 ms (bom_01, mri_00) or 200 ms (las_29, ten windows) with no other check, which is not always enough for the old ones to close; together with the bug above, too many open windows corrupt memory. |
| `src/driver/msgdrv.c`, `msgWindow_Entry` (the allocation before the `strcpy`) | all | The message copy is allocated with `strlen(msg)` bytes, without room for the terminator, so `strcpy` writes one byte past the block. |
| `src/mario/mario_motion.c`, `mot_talk` (the `fbatGetPointer()->npc` read) | all | Mario's pose change after a conversation uses `fbatGetPointer()->npc`, the NPC Mario last talked to or fought, which may belong to another map. |
| `src/event/evt_map.c`, `evt_map_blend_set_flag` (the `"party"` branch) | all | No check that a partner (or a follower) is out: `partyGetPtr` returns NULL for id -1 and the partner's animation group is read through a null pointer. |
| `src/mario/mario_pouch.c`, `pouchInit` | all | `pouchInit` allocates a new inventory without freeing the old one. It runs at boot and again when a new file starts, so the first block leaks. |
| `src/driver/msgdrv.c`, `msgAnalize` (the `<select>` tag's `sscanf`) | all | The format has five `%hd` but only four pointers follow, so a `<select>` tag with a fifth number writes it through whatever is in the next argument register. |
| `rels/mri/src/mri_puni.c`, `puniModeWonder` (`p->effect = effPuniBalloonEntry(1, ...)`) | JP and the early demos (fixed in US) | The Puni keeps its bubble-pop burst in `p->effect`, but the burst deletes itself after 30 frames, and `effEntry` hands that slot to the next new effect, often another Puni's bubble (`puniModePreupdraft`). A later `effDelete(p->effect)` on the old pointer (the mode changes in `puniModeChangeAttack`/`Away`/`FallCheck`, `puniModeHagure`, `puniDeleteEffect`) then deletes that other effect and frees its work, while its Puni keeps writing its position into the freed block every frame (`puniModeUpdraft`), corrupting the effect heap. Reported by Zephiles (2026-11-11), who connects it to a crash in the JP Puni rooms. |
| `src/driver/lightdrv.c`, `lightEntry` (the `name_0000` loop) | all | When the name is taken, the loop formats `uniqueName` from `name` and then points `name` at `uniqueName`; on a second clash `sprintf` reads its own output buffer, so the suffixes stack up (and the copy overlaps). |

## Softlocks and unusable saves

Reported by Zephiles (2026-11-11) and checked against the code.

| Where | Versions | Bug |
|---|---|---|
| `src/driver/msgdrv.c`, `msgWindow_Main` (`MSG_WIN_STATE_REVIEW_KEY_WAIT`) | JP and the early demos (fixed in US) | While paging back through a message, several buttons are handled in the same frame. With the window two or more pages back, B and Z together set the last page and then step back one page into `REVIEW_UP`, whose scroll test never passes for a page further down; nothing leaves that state and the window never closes. |

| `rels/jon/src/jon.c`, script `dokan_open` (`evt_cam_letter_box_wait`) | JP and the JP demo (fixed in US) | After a Pit of 100 Trials floor's enemy dies, the exit-pipe script turns Mario's controls off and waits for the letterbox bars with no time limit. `camLetterBox` only brings the bars in while no partner ability is in use (and the letterbox is not disabled), so if they cannot come in the script never continues and the pipe never rises. US waits a fixed second instead. Reported by Zephiles (2026-10-26) from cases on the first Pit floor, JP only; the player state behind those cases is not confirmed. |
| `src/manager/filemgr.c`, `_fileAlloc` (`while (search->entry) {}`) | JP and the early demos (fixed in US) | Asking for a file whose asynchronous read is still running busy-waits for the DVD thread to finish it, but that thread has the same priority as the main thread and never gets to run, so the game hangs. | `src/mario/mario.c`, `marioCheckMenuDisable` (the Vivian test) | JP and the early demos (fixed in US) | While Mario hides in Vivian's shadow the pause menu is allowed even when a script is using Vivian (`PARTY_FLAG_IS_EVT_USE`), so it can open in the middle of that script. |
