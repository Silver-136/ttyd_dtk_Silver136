# Fakes

Policy: no new fakes; the ones listed here are debt to be replaced by natural C. A fake is a behaviour-identical C trick (extra temp, no-op cast, dead guard, padding, inline helper, pragma) that makes the compiler emit the target code or layout. No fake uses assembly: there are no asm blocks or asm-backed functions in place of C.

Every fake is marked at its site with a `// FAKE: ...` (or `/* FAKE: ... */`) comment and has a row here, one row per function. Cleanup means replacing a fake with natural C that still matches (both builds byte-identical: `cleanup_tools/verify_both.ps1`), then deleting its comment and its row.

This list is built from the FAKE comments in src/, rels/ and libs/. It covers both versions: the Version column says where a fake is active, JP (G8MJ01 only), US (G8ME01 only, inside `#ifdef VERSION_G8ME01`) or Both (shared code). The Fake column summarises the comment text; "see comment" in the last column means the natural shapes tried are in the comment or were not recorded.

Why a no-op cast or a spare temp can change the output: MWCC builds an expression tree for every statement, and the code generator works from that tree, not from the C semantics. A redundant cast such as `((PartyEntry*)party)->moveFrames`, where `party` already has that type, or a value parked in an extra local, is an extra node. Folding it away comes late, so earlier passes still see it. That changes three things. First, scheduling and CSE: a byte-offset access `*(T*)((u8*)p + K)` is an indirect load, a field access is a member load, and the passes treat them differently, so the order of loads or of an address add can move. Second, register colouring: each named local or inline temporary gets its own virtual register and number, and the allocator colours in number order, so the same value through a temp can land in another register. Third, inline cost: with `-inline auto,deferred`, whether a callee is inlined depends on the caller's estimated size, which counts tree nodes; removing a cast can bring a caller under the limit and pull a whole callee in (see npcdrv fbatHitCheck). The no-op cast fakes added in the structs cleanup (party.c, mot_roll.c, ac_stick_rotate.c, npcdrv.c) all replaced raw byte offsets. They keep the original tree shape but name the field, so the struct layout is the single source of truth while the bytes stay identical.
