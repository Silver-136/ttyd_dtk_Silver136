# Name provenance

The names below were **invented** by the LLCOOLT project (commits `51126e7d`, functions, and `a87cca5f`, data
labels). They describe what the code or data does; they are not original names from a symbol map. Kept for
readability (decision 2026-10-24). Replace one only with stronger evidence (an original name), and then remove
its row. First generated by `cleanup_tools/name_provenance.py` from the JP `symbols.txt` diffs of those commits;
`US` says whether the US config uses the same name.

Functions: 142 (2026-11-09: original names from comparing our linker maps with the JP demo maps: mario_land_kemuri is mario_kemuri_landon (whose old name was the stripped kemuri_water), partyChgWalkPose partyMoveAnime, evt_unitwin_select_func select_func, lecture_step_wait wait, rsh_texmtx_tbl texmtx_tbl, jetw_ry_tbl dat_ry, zakoM2D_find_start_event zakoM2D_find_event; 2026-11-09: yoshi_damageToge is the JP demo map's damageToge (same size); yoshi_animTimeMain became the original yoshiAnimeCtrl, partyRestoreRunMode partyPrevRunMode, partyPlaySfxFootstep partyWalkSe and partyGetTargetHeightDiff partyGetTargetDistY, all from the JP demo map). Each listed function has a comment at its definition giving the placeholder it replaced. Data labels: 109 (2026-11-10: evt_sub_mail_event_end was the last word of evt_sub_mail_event (one object in the JP demo map), merged; 2026-11-09: original names from comparing our linker maps with the JP demo maps: mario_land_kemuri is mario_kemuri_landon (whose old name was the stripped kemuri_water), partyChgWalkPose partyMoveAnime, evt_unitwin_select_func select_func, lecture_step_wait wait, rsh_texmtx_tbl texmtx_tbl, jetw_ry_tbl dat_ry, zakoM2D_find_start_event zakoM2D_find_event; 2026-11-09: of the 1757 data rows listed before, 1625 were compiler labels and 19 were names for objects the original left unnamed; both now have their own sections below; 2026-11-09: nise_mario_init (las_29) and gesso_arm_wait_event (tik) are the JP demo REL maps' last_evt_3_npc_entry and test_event; 2026-11-09: g_moamoa_chain_num is the JP demo map's g_moamoa_chain_max; 2026-11-09: sSinTbl is _getHammerPoint's local initializer (JP demo @2031) in every version; 16 labels dropped on 2026-11-08: they were compiler-made local initializers or literals in the original (JP demo map @N names), now written that way; 167 rows for labels no version uses any more, such as the removed math statics and `shadow_lbl_*`, were dropped on 2026-11-07; four more turned out to be original JP demo map names and were taken off the list on 2026-11-07: `texmtx_tbl` in envdrv, `testenemynpc_move_event` in npc_event, `monte_p` in yuu_00, and `partyGetTargetMovespd`, a party_move function the generator had listed as data).

Caveats: the function commit says 3 of its names were taken from reference projects (silver136, nwp_pm2);
they are not identified here. The data name `white` also appears in our earlier US-only config and may predate
the renaming.

## Credits for inherited struct field names

Many struct field names in the battle, pouch and item headers (for example the BattleWeapon status
chance/time fields, BattleUnitKind offsets such as `bintaHitOffset` / `kissHitOffset` / `cutBaseOffset`, and
BattleWork / BattleUnit counters) came with the adopted tree and follow the structure notes of jdaster64's
ttyd-utils project and its ttyd_structures_pseudocode.txt. Credit for those names goes there; jdaster64 has agreed
to their use (2026-10). The battle unit / part / token flag names follow that document (kIsWinged,
kJumplikeCannotTarget, kCeiling, kChargeExpended ...); our comments say what the code does with each bit. Where the
code contradicts a name, the code wins: part bit 0x80 (WeakToAttackFxR there) is read by US BattlePreCheckDamage as
"add unit work slot 1 to the part's defence", so it is kPartUnitWorkDefense here.

## Credits for icon names

The descriptive icon names in include/icon_ids.h that do not come from our code or the item table (373: the 337
former `ICON_xxx` placeholders and the 36 US-only language variants of text icons) are Zephiles' IconType
enum from the TTYD Practice Codes, checked by Zephiles on the retail versions and given to this project for use
(2026-11-05). Two spellings were corrected (`ICOn_` -> `ICON_`, `HANMER` -> `HAMMER`) and the colour-text
names follow one order (`ICON_TEXT_GREEN_*`, `ICON_TEXT_BLUE_*`). They name what an icon shows, not an
original symbol. Where our code-derived names and Zephiles' name the same icon, ours stay; the ids matched ours
everywhere, and nine US ids we had marked as inferred take those values.

`DrawMenuMarioPinchMark` and `DrawMenuPartyPinchMark` (battle_menu_disp.c, US and later, also both September 2004
demos) are Zephiles' names: the JP demo's map has one `DrawMenuPinchMark` (0x2c8) that draws both marks; from
the September demos on, `DrawMenuPinchMark` (0x58) only calls the two halves in an order that keeps the front mark
on top. The stem is the original name; the Mario/Party parts follow `BattleGetMarioPtr`/`BattleGetPartyPtr`.

## Credits for TRK names

The MetroTRK constant names in `libs/trk/include/trk.h` (DSError values `DS_NoError` ... `DS_InvalidProcessID`,
`DS_OSError`, `DS_Error800`; reply errors `DSREPLY_NoError` ... `DSREPLY_InvalidThreadID`; `DSSTEP_*`, `DSIOResult`
`DS_IO*`, `DSFileHandle` `DS_Std*`; the `DSMSG_*` command ids) are the spellings the community TRK decompilations
share (projectPiki/pikmin2, ACreTeam/ac-decomp, zeldaret/tp, all CC0), taken to be MetroTRK's own source
spellings (not proven by a symbol map: enum names leave no symbols). They replace the descriptive `DSERR_*` / `DSREPLY_*` names we had invented (2026-11-07). The
values were checked against our handlers; the comments in trk.h say where this code returns each.

## Credits for hardware register names

The register index and bit names for the PI, MI, DI, SI, EXI, AI and DSP registers in
`libs/dolsdk2004/include/dolphin/hw_regs.h` (`PI_INTSR`, `MI_PROT_TYPE`, `MI_IRQ_*`, `DI_SR`, `DI_SR_TCINT`,
`DI_CMD_*`, `SI_POLL_IDX`, `EXI0_CSR`, `EXI_CSR_EXTINT`, `AI_CR`, `DSP_CSR_*`, ...) come from public hardware
documentation: the mnemonics of YAGCD ("Yet Another GameCube Documentation", chapter 5, gc-forever.com/yagcd) and
the register and field names of the Dolphin emulator's hardware code (github.com/dolphin-emu/dolphin,
Source/Core/Core/HW/); the `DSP_CSR_*` and `DI_CMD_*` names follow Dolphin's, the others mostly YAGCD's.
The definitions are our own; they are not original SDK names. Sources and tables:
`cleanup_notes/hw_register_names.md` (outside the repo).

## Credits for MusyX state names

MusyX state and type names follow AxioDL's MusyX decompilation (github.com/AxioDL/musyx, CC0); they were invented
there and are not original names: `STREAM_STATE_*`, `STREAM_TYPE_*` (stream.h), `SEQ_STATE_*` (seq.h),
`DSP_VOICE_STATE_*`, `DSP_STUDIO_STATE_*`, `DSP_PB_STATE_*` (dspvoice.h), `ADSR_MODE_*`, `ADSR_STATE_*` (adsr.h),
`VS_STATE_*` (voice.h), `HW_MESSAGE_*` (hardware.h), `SAL_SRC_*` (sal.h) and `SYNTH_FLAG_*` (synth.h). The
definitions are ours, each value checked against our code (2026-11-07). For sample formats our own
`SAMPLE_COMP_*` names (synthdata.h) stay; AxioDL's `SAMPLE_TYPE_*` are the same values.

## Credits for restored function bodies

Functions the JP demo's linker maps list as UNUSED (stripped) carry their original names; where nothing in the game
calls them, only their size can be checked against the map, so their bodies are reconstructions, not proven
retail code. Bodies from others: `addHeadCheck`, `addTail` and `pouchGetItemCheck` in `src/mario/mario_pouch.c`
are NWPlayer123's reconstructions (the early-return `addHeadCheck` gives `pouchGetItemCheck`, which inlines
it, the map's size); `memcmp_as4` in `src/system.c` follows Super Paper Mario's (github.com/SeekyCt/spm-decomp, CC0). The analysis of the remaining matching tricks used mweppc
(github.com/doldecomp/mweppc, CC0), a decompilation of the Metrowerks compiler.

## Compiler labels (not names)

1625 more data labels came from the same LLCOOLT commit (`a87cca5f`) but are not names: they are compiler labels
(`@N`) for string literals, float constants, jump tables and local initializers. Our source writes these objects
as literals, so they have no name in the code; the number is only the compiler's own counter, and the label in
`config/*/symbols.txt` need not match our build's number. Checked 2026-11-09 against the symbols of our JP build
and the JP demo's linker maps:

- 566: the JP demo maps show a compiler label for the same object, so the original had no name either.
- 1059: objects the JP demo maps do not cover (code or data added after the demo, or parts of areas the demo
  lacks). Same kind of object; in every covered case the original had no name too, and none of our compiler
  labels lines up with a named object in the maps.

Their rows are no longer listed here; the full list is in this file's history (before 2026-11-09).

## Names added in this fork

one turns up. The table lists the first ones (to 2026-10-25). Since then many more enum, flag, constant, field and
